定子底座 + 套环合体件。v1 的 `baseplate_collar` 保留不动，这个是 d100 变体。

## 2. flange_disc / mounting_flange

定子法兰盘 + 翻转扣顶的安装法兰。**从 v1 沿用至今，v3 期间没改过。**

值得记的只有一条装配约束：mounting_flange 是**绕 X 翻转 180°** 扣上去的
（`(x,−y,28−z)`），套环 13 + 法兰 7 + 3 = 23 = 凸台高度，全部在 Z=28 齐平。

## 3. hub_disc

转子毂盘，直接贴电机转子面。**这个件上发生过一次完整的"提方案→用户否→回滚"。**

### 加裙边又撤掉（07-13 → 07-14）

诊断出**电机↔hub 接头是整机刚度瓶颈**：4×M3 菱形（对角 12/15），力臂只有 6~7.5mm，
到屏顶放大 30 倍。我提了个 bell-clamp 裙边（ID50.3/OD58×3.2 + 6 条压筋）。

> **"hub_disc还是改回去吧"**

一句话撤回。STL / SCAD / 图纸全部回滚。

**但诊断结论保留** —— 缓解手段退回到：100% 填充 + 6-8 层壁、大垫圈 + 正确力矩 + 隔几天复紧、
动平衡、VHB、688 预压。裙边设计存档，随时可以要回来。

### 后续改动

| 日期 | 改动 |
|---|---|
| 07-14 | 16 个 PCD 环孔底面沉孔 Φ4.2×4→**×4.5**（腹板 1.5→1.0，压螺母要轻） |
| 07-21 | **改正放**贴电机（原来是翻转的），中心菱形沉孔朝上 |
| 07-21 深夜 | **凸台让渡**（用户口述）：上凸台 Φ60→**50**，下凸台 Φ80→**70**，内圈 8 孔 PCD Φ70→**Φ60** |

"凸台让渡"是和 rim_ring 联动改的 —— 径向定心从中孔转移到了新增的内凸台环。

## 4. rim_ring

**改动最多的转子件**，因为它一路吸收了别的零件的职能。

### 大改：吃掉一整个零件（07-20/21）

原本转子上有独立的 `mlkpai_carrier_disc` 承载盘。这次**整个取消，功能并入 rim_ring**：

- rim_ring **翻过来**，托盘平面朝上，自己当承载面
- 托盘 BASE_H 3.5→**5**（要塞 Φ4.2×4.5 铜螺母窝），总高 9→10.5
- **并入 7 个 pi2hub 安装孔**
- 外唇两个角度缺口**全删**→ 完整整圈（互锁不要了）
- 承载面从 45.7 **降到 42.2**，上面挂的东西全部跟着降 3.5

### 同期的其它改动

| 日期 | 改动 | 备注 |
|---|---|---|
| 07-20 | 扇形挖槽 R40..OD → R35..R61 | |
| 07-22 | 挖槽内径**又改回 40** | 正好从内凸台环外缘起，不跨槽 |

| 07-21/22 | +4 个 wifi 沿孔 | wifi 改放平方案 |

### wifi 盒位的两次迭代（07-22 晚）

> 用户要求向 pi2hub 靠 3mm → XC 46→**43**（壳壁-板边隙 4.8→1.8）
> 再沿长边平移 **−15**

但 −15 时最内孔的沉孔边 r39.5 **侵入内凸台环 R40 达 0.5mm**。用户要求消除 → 算得临界 d≤14.28，
取 **−13** 留 0.9 余量。三档滑位方案作废，只留定稿单组 4 孔。

**交互特征**：用户给方向和量（"靠 3mm""平移"），我算边界并把越界处报回去，用户拍板取值。

## 5. portal_tee_v3

屏幕底部支撑 T 型件，同件 ×2（第二件转 180°）。**这个件是从一次彻底推翻里长出来的。**

### 推翻：三个件一次性作废（07-22 深夜）

v3 原本用 `screen_plate_v3`（中央板）+ `gantry_v3`（龙门）+ `top_cap_v3`（对称夹舌帽）。
用户一次性给了 4 条：

> **"中央板不要"** / **"2·3 按建议"** / **"删 M6 配重孔"** / **"体积最小，转子收进 Φ170"**

三个件全部作废，重新长出两个新件：`portal_tee_v3` + `top_cap_v3_1`。

### T 件的四轮定稿

| 轮次 | 用户输入 | 结果 |
|---|---|---|
| v1 | — | 初版 |
| v2（07-22 深夜） | **切片反馈** | 筋齐一侧 + 顶平板托梯形 + 平躺打印 |
| 07-23 | **图纸红线：补全成梯形** | 梯形加强壁斜边直达托外缘，正视轮廓 = 整梯形 |
| 07-23 | **用户问出**："Φ7 帽会不会咬到竖梃？" | 实测咬 0.9mm → 托底加 Φ7.5×4 让位窝，布尔验证交集 0 |

### ⚠ 一个被用户切片发现的 bug

前一版托下有个小筋 `tri_yz`，**旋转变换算错，整块飞到件外悬空**。
manifold union 不报错、也不检查连通性，所以我这边完全没察觉。

**用户在切片软件里看到了那个悬浮三角块。**

教训（已写进记忆）：**多方向 CrossSection 旋转挤出必须验证落点 + 连通体数（decompose）**。

## 6. top_cap_v3_1

顶部薄压条。**全项目迭代最密集的件** —— 光是排针尾槽就有 4 次连续 git 提交。

### 从厚块到薄条（07-22 深夜）

> **"只连两个 M3 孔，做薄"**

31.75 厚的压梁块 → **18×140×7 扁条**，体积掉 77%（~22g）。

### 光电大改：六轮

原方案光电在转子外围 r113。

> 用户嫌 **r113 太大**

→ 搬到顶部轴心区，贴压条顶。然后是六轮修正：

| 轮次 | 用户输入 | 结果 |
|---|---|---|
| 一改 | — | 囚窝方螺母 + 盲槽支撑岛（**走了弯路**） |
| 二改 | **用户纠正 ×2** | 改回老 v2 支架孔型：2×Φ3.2 平通 + 底面头窝 |
| 三改 | **"挪到 18 宽正中"** | 孔位移到条中线 |
| 四改 | **"旋转会不会挂？"** | 扫掠核算发现**弦偏移使叉臂扫带加宽，刀片净通道余量只剩 0.7** ✗ → 模块外移到 capY−45，净通道 r44.7..51.9，双侧余量 2.1 ✓ |
| 五改 | — | 排针尾避空槽 |
| 六改（07-24） | **"光轴过圆心，且不加宽压条"** | 模块绕两孔连线中点 M(0,−45) 转 **asin(17/45)=22.196°** → 叉臂扫掠变成干净同心环，净通道 r36.78..46.66（宽 9.9），余量 ~3.4/侧 |

期间还有：沉孔 Φ6.5→**7.5**（用户："小了"）；曾试加翼板方案被否（"不加宽"）。

### 排针尾槽：4 次连续提交

git 里 07-24 这天有 4 个连续 commit，全是这一个槽：

```
排针尾避空槽宽 3→6
排针尾避空槽宽 6→7
排针尾槽定为 9×6 (长+1, 宽回 6)
排针尾槽 9×8, 对称于两孔连线
```

**交互特征**：这是典型的"用户看着实物/切片，一次给一个小增量"的节奏。

### 一个关键方法论收获

四改那次，用户只问了一句 **"旋转会不会挂"**，就把一个快照布尔查不出来的问题挖出来了：
**偏心布局的件，静态不干涉不等于旋转安全**。此后新增了全周扫掠校核 `check_v3_sweep.py`
（5° 步进 × 转子顶部件 × 静止件）。

## 8. vane_slider_v3

光电挡光片。**这个件是被"制造公差不可控"逼出来的。**

### 三次架构变化

**① 静止挡光片直接长在 frame_B 上（07-23 二改）**

> **"可以直接做到短臂顶架吗？"**

→ 3(径)×4(切) 的 fin 直接长在 frame_B 的 ang=90 臂筋底，B 翻转打印时立在筋顶，零支撑。
省掉了原来的 vane_clip_v3 夹块（连带省了 M3×30+螺母）。

**② 改独立可调滑片（07-24）**

> **"4 根 M8 螺柱长度不稳定 → 顶架实际高度不定，frame_B 长死的刀片废除"**

这是个**制造现实**问题：买来的螺柱长度有偏差，顶架的实际高度装出来才知道，
所以刀片高度不能在 CAD 里定死。

**③ 逐步简化到终版（同日二/三/终版）**

用户一路砍复杂度：

| 试过的 | 结果 |
|---|---|
| 长槽 ±2.5 | 否 |
| 长槽 ±1.2 | 否 |
| **终版：两件都普通圆孔，无槽** | ✓ |

**高度调节方式 = 刀片印长 42（全件 50），装机时按实际架高用刀剪短。**
规则：刀尖距压条顶面 12mm。

> 四改，用户 **"板顶到底"**

板 16×8×4 恰好填满筋侧面（底平筋底 asm290 / 顶抵臂底 asm298），
装的时候向上顶到位就定位了，还防转。（用户以为该 16 → 实为 8，因为臂比筋每边凸 7 挡住了。）

### 一个细节

另出了一个**已剪短的孪生** `vane_slider_v3_asm.stl`（刀尖 280）专供装配/干涉校核 ——
因为打印用的 STL 是全长件，直接装进装配里**必撞压条**。校核必须用孪生。

## 9. wifi_shell

**返工次数最多的件。** 记忆里专门为它留了一条教训。

### 第一轮：三次返工（07-09）

我先后给了：平放两件式 → 一件式 ⊓ 罩 → 用户自己的侧立方案。

**教训（已写进 `feedback_simple_fixtures_first.md`）：**
> 固定件先给最简单件方案；**用户常自带摆放方案，按字面重建**，别自作主张优化。

### 第二轮：侧立 → 放平（07-21）

| 日期 | 用户输入 | 结果 |
|---|---|---|
| 07-21 | **切片图红标 + 更正**："沿在开口面一侧，与缺的面共面" | 沿的位置改正 |
| 07-21 晚 | 选**"放平/手动改"**路线 | 旧 wifi_box 废，新件 `wifi_shell` |
| 07-22 | 盒位定稿两次迭代 | XC 46→43，长边平移 −15→−13（见 rim_ring 节） |

### ⚠ 一个顺序 bug

挖出口窗时窗被沿板填回去了，造成 **168 mm³ 干涉**。

**教训：挖窗必须放在加沿板之后**，先挖后加会被 union 填回来。
（07-27 砍脚时同样的坑又出现了一次 —— 裁切也必须放最后。）

### 第三轮：砍脚（07-27，本次会话）

> **"我理解wifi这个件要改一下，有个脚出来了，要砍掉"**

−Y 端沿外角伸到盘系 r=90.22，是全机唯一探出 Φ170 盘缘的结构件。
裁切半径被一颗螺丝钉死（R81.5 会废掉螺丝并牵连 rim_ring 重印）→ 取 **R83.5**。

## 跨零件的交互模式

把 7 周的过程摊开看，有几个反复出现的模式：

### 1. 用户的高频有效动作是"看切片软件"

至少 5 次真 bug 是用户在切片器里看出来的，不是我算出来的：

- baseplate_collar 内外开口高度不齐（6 vs 8）
- baseplate_collar 螺母窝会撑爆 1.65mm 壁
- portal_tee 托下**悬浮的三角块**（manifold 不报错）
- wifi_shell 沿的位置画错了
- portal_tee 顶托的 Φ7 螺丝帽咬竖梃

**我的几何是"算对的"，但物理上不对/打印不出来的，几乎全靠用户目检发现。**

### 2. 用户的一句反问 = 一个新校核维度

| 反问 | 逼出来的东西 |
|---|---|
| "旋转会不会挂？" | 全周 5° 步进扫掠校核（快照布尔查不出偏心布局的旋转干涉） |
| "这些干涉有检查吗？" | 紧固件头建模参与让位（装配孪生里从来只有塑料件） |
| "模拟一下安装过程" | 三段运动模拟（快照布尔 ≠ 可装配性） |

三次都是**方法论层面**的补强，不是单个数字的修正。

### 3. 用户给方向，我算边界，用户拍板

典型对话形状：

> 用户："向 pi2hub 靠 3mm，再沿长边平移 −15"
> 我：−15 时最内孔沉孔边侵入内凸台环 0.5mm，临界值 d≤14.28
> 用户：取 −13

用户负责**意图和物理直觉**，我负责**把约束边界算出来并报越界**。

### 4. 推翻比修补更常见

- `hub_disc` 裙边：加了又撤（"还是改回去吧"）
- `screen_plate_v3` + `gantry_v3` + `top_cap_v3`：一次性三件作废
- `wifi_box` → `wifi_shell`：整件重做
- `vane_clip_v3`：方案作废，脚本留档 STL 删掉
- 罩子的 M3×55 方案：用户一句话推翻

**用户不倾向于在坏方案上打补丁。** 这对我的启示是：给方案时要说清代价，让推翻发生得早一点。

### 5. 迭代粒度很细

top_cap_v3_1 的排针尾槽 4 次连续提交（3→6→7→9×6→9×8），
vane_slider 一天内二改/三改/四改/终版。用户习惯**小步快跑**，
所以每次改动都要保证**可重跑、可回滚**（参数化 + git）。

## 沉淀下来的技术教训

按被踩的先后：

| # | 教训 | 出处 |
|---|---|---|
| 1 | CrossSection 用 `[[...]]`；CW 绕向 → CrossSection 为空 → 后续 union 全变 0 体积 | 早期 |
| 2 | 固定件先给最简单件方案；用户常自带摆放方案，**按字面重建** | wifi 盒三次返工 |
| 3 | 挖窗/裁切必须放在**所有加料之后**，否则被 union 填回 | wifi_shell ×2 |
| 4 | 多方向 CrossSection 旋转挤出必须验证落点 + **连通体数**（manifold union 不报错也不检查连通性） | portal_tee 悬浮块 |
| 5 | 读"翻绕向导出"的 STL 做布尔要修绕向，否则**流形负体积 → 交集恒 0 = 假阴性** | check_v3_clash |
| 6 | STL 三角汤转 Manifold **必须先合并顶点**，否则 0 体积非流形 | 本次会话 |
| 7 | 快照布尔不证明旋转安全，**偏心布局必须全周扫掠验证** | top_cap 四改 |
| 8 | **紧固件头是几何的一部分**，靠近内壁时必须建模参与让位 | 本次会话 |
| 9 | 快照布尔 **≠ 可装配性**；悬空障碍件必须做下落扫掠 | 本次会话 |
| 10 | 深井里的螺丝要给引导锥，**捕捉半径 > 最大横向游隙** | 本次会话 |
| 11 | 布尔判据要设**物理阈值**（圆柱多边形逼近会造纳米级假交集）；别把互斥状态叠在一起测 | 本次会话 |
| 12 | 侧挂件的径向带要用 hypot 修正，不能直接取坐标 | vane_slider |
| 13 | 打印用 STL 和装配校核用 STL 可能**必须是两个文件**（剪短前/后） | vane_slider |
| 14 | 厂商渲染图**不能信**（尺寸压缩）；图像测量锚定 2.54mm 排针节距 | 米联派 |
