## 1. 需求：一句话

> **"增加罩子，把屏幕以下电路部分遮盖住，下面锁到转子的件上面整体看起来要是一个圆柱的样子"**

这句话里有 4 个约束：遮盖范围 (屏幕以下)、固定对象 (转子件)、固定位置 (下面)、
外观 (圆柱)。但还有 4 件事必须定死才能画：

先做占位扫描，把"待遮盖区"量清楚，再带着**实测数据**提问 —— 不是问偏好，
是问那些"选项不同则零件完全不同"的岔路：

| 问 | 用户选择 |
|---|---|
| 直径 (Φ176 外套 / **Φ170 齐盘缘** / Φ180 宽松) | **Φ170 齐盘缘** (要求最高，需为 T 脚开让位) |
| 分件 (一体整圈 / **两半对开** / 卡扣) | **两半对开** (维护可单独掀开) |
| 顶部 (**封顶带屏缝** / 开口筒 / 封顶+散热环缝) | **封顶带屏缝** |
| 开口 (出线口 / 散热孔 / 维护窗 / **全封闭**) | **全封闭，先不开** |

扫描同时暴露了一个硬约束 —— 见下节。

## 2. 用户中途插话，砍掉一个"脚"

> **"我理解wifi这个件要改一下，有个脚出来了，要砍掉"**

扫描确实发现：`wifi_shell` 的 −Y 端沿外角伸到盘系 **r = 90.22**，
是全机**唯一探出 Φ170 盘缘的结构件**。加罩子后必然打架。

裁切半径不是随便选的，被一颗螺丝钉死：

| 裁切半径 | 最外那颗沿孔 (中心 r79.06) 外剩料 | 后果 |
|---|---|---|
| R81.5 (罩子完全不用让位) | 0.34 mm | 废掉该螺丝 → rim_ring 沿孔要挪 → **承载盘重印** |
| **R83.5** ✓ | **2.34 mm** | 4 颗沿螺丝全保住，**rim_ring 不动** |

做法：在 `build_shell.py` 末尾用与转子轴同心的 R83.5 圆柱求交。
削 239 mm³ (1.0%)，r_max 90.22 → 83.50，内腔角 r79.54 不破腔。

⚠ 裁切必须放在**所有加料/挖料之后**，否则会被后续 union 补回来 (07-22 挖窗踩过同样的坑)。

## 3. 壁厚

> **"厚度3mm就行我理解，需要加强的地方加强就行"**

壁 3 / 顶板 3，加强放在三处：

1. **4 根固定立柱兼竖筋** (本来就要有，顺便当加强)
2. **接缝 bolster** — 内壁在 |Y|≤4 局部加厚到 ID152，对开面加大 + 自由边加劲
3. **屏缝下翻边** — 顶板最长的自由边加个下翻边，兼装屏导向

---

## 4. 固定方式：被"封顶"逼出来的方案

这是整个设计最纠结的一环。**封顶之后，所有底部固定点都被自己的顶板盖住，
螺丝刀伸不进去。** 依次否掉：

- 底部压耳 → 装完够不着
- 卡簧 / 滑入式卡口 → 屏缝卡着屏幕，罩子根本没法转动就位
- 顶板开维护孔 → 违反"全封闭"

第一版方案：**Φ3.4 细孔 + M3×55 长螺丝**，从顶板一路穿到底。

> **"锁螺丝的位置能不能让螺丝没有这么长，这个螺丝头部直径是7.5mm，
> 我理解只要螺丝这个位置沉下去就行，你理解我的意思吗"**

用户的改法更好，直接推翻第一版：**把立柱掏成上下贯通的沉井，短螺丝坐井底，
头沉在井里，长螺丝刀顺井下去拧。**

```
Z50 ┬─────┐ ← 井口开在顶板上 (Φ9)
    │  ▓  │
    │  ▓  │   井深 47, 长螺丝刀顺井下去拧
    │  ▓  │
 Z3 ├──▄──┤ ← 螺丝头 Φ7.5 坐这儿, 沉在井里不露头
 Z0 └──╂──┘ ← 3 厚台肩 + Φ3.4 过孔 + 45° 引导锥
```

好处：螺丝 **M3×55 → M3×12**（标准件）；拧紧力矩不再压在 47mm 长的 PLA 柱上，
而是直接压在 3mm 台肩上；立柱到顶与顶板融合，比原来多一段加强。

螺丝长度是卡死的：头底在装配系 45.2 → 台肩 3 + 托盘 5 + hub 实体 1 = 到铜花螺母顶 36.2，
杆到 33.2 旋入 3.0mm。**M3×14 会到 31.2，探出 hub 底 0.5mm 顶到电机端面，只能用 12。**

立柱加粗 (Φ10→Φ14) 后又发现 157.5° 那根被 wifi 壳的让位窝啃到，
井壁最内 0.5mm 环只剩 99.1% 实心（内侧破了个 ~6mm³ 的口）。
把让位间隙从 0.6 收到 0.4 修掉（都是同步共转的邻居，0.4 只需覆盖打印公差），
顺带把 T 脚让位窝的外皮从 0.79 提到 0.99。

## 6. 用户再追问，抓出两个真 bug

> **"锁这两个半圆的时候，这个螺丝帽要通过全部的这个孔，你需要模拟一下螺丝的安装过程"**

这句话逼出了 `sim_install.py` —— **快照式布尔只证明"装好后不打架"，
不证明"装得进去"。** 三段运动模拟：

| 段 | 内容 |
|---|---|
| A | 半罩竖直下落 h=60→0，26 个高度 × 8 个邻居 |
| B | M3×12 落井：自由落体 z52→15 满偏心 ±0.75 + 导入落座 z15→3 偏心 ≤0.2，各 8 方位 |
| C | Φ7 螺丝刀通道从井口 asm92.2 直上机顶 vs 全部静止件 + 转子上部件 |

### ★ Bug 1：半 B 装不下去

线缆出口做成"窗"，只在最终位置对齐。罩子下落到最后 9.5mm 时，
窗上方的筒壁会砸在悬空的 wifi 线缆头上（61.8 mm³）。

修法：让所有让位体做**向下扫掠** (`sweep_down()`，倍增法 log 次并集，深 14mm)。
悬空特征的窗自动变成通到底边的槽。落到 Z0 的障碍件扫掠是空操作，只有线缆头受影响。

### ★ Bug 2：螺丝会杵在井底不进孔

头 Φ7.5 在 Φ9 井里有 ±0.75 横向游隙，落到井底时杆尖最多偏离过孔 0.75mm，
正好卡在台肩上 —— 井深 47mm，掏不出来。

修法：孔口加 **45° 引导锥 Φ3.4→Φ5**（Z2.2–3.0）。捕捉半径 1.0 > 0.75 ✓，
头仍压在 Φ5–Φ7.5 环面上（承压环宽 1.25）。

### 两次假阳性（值得记住）

1. 多边形逼近让 Φ7.5 头在 Φ9 井里"相切"时产生纳米级假交集（最大 0.0001 mm³）
   → 判据阈值取 0.05 mm³，并打印实测最大值自证
2. 早期把"满偏心"和"已落座"叠在一起测 = 测了**互斥状态**，必然假报警
   → 按运动阶段分段设偏心上限

## 7. 减重

罩子 193 g 且几乎全在 r≈85 —— 极惯量增量很大，动平衡要重做。

> **"1.减"**

顶板 3 → 2，**193 g → 171 g**。

⚠ 此处有一次口误更正：先前说"省约 46g"算错了一倍。板面积约 187 cm²，
减 1mm = 18.7 cm³ ≈ **22 g**。

刚度没问题：顶板转动时受的是**面内张力**不是弯曲（离心力沿径向），2mm 够；
翻边随之从 6 深变 7 深还多补了点。

## 复盘：这次协作里什么起了作用

**用户侧提供的，是模型里没有的信息：**

- "有个脚出来了" —— 装配预览里看出来的，扫描确认后是全机唯一探出盘缘的件
- "螺丝帽直径是7.5mm" —— 手上实物的规格，数字孪生里根本没有紧固件
- "让螺丝没有这么长" —— 对可采购性和装配手感的判断
- "模拟一下安装过程" —— 指出了校核方法本身的缺陷

**四次追问里有三次直接抓出了错误**（悬出的脚、没建模的螺丝头、装不进去的下落路径），
一次推翻了不好的方案（M3×55）。

**教训沉淀（已写进项目记忆）：**

1. 快照布尔 ≠ 可装配性，悬空障碍件必须做下落扫掠
2. 紧固件头是几何的一部分，靠近内壁时必须建模参与让位
3. 深井里的螺丝要给引导锥，捕捉半径 > 最大横向游隙
4. 布尔判据要设物理阈值，圆柱多边形逼近会造纳米级假交集
5. 模拟运动时不要把互斥状态叠在一起测
